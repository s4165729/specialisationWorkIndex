About the Prototypes

For this assignment i have explored three different ideas, building two parallel Prototypes for each. I built two ideas side by side for each which let me compare what kinds of different approaches i could take towards the same idea, rather than commiting to my first solution etc stright away this process let me think about this in detail on how this could work. Each prototype below links to the live version and it's full commit history and explanation.

Idea 1: Spacial Awareness using sound

This idea explores whether the position on a screen can be understood by sound alone. Instead of looking at where something is, the person moves a circle and listens, using a pitch and note changes tell them where they are in the space.

Prototype 1: Dot sound prototype

Press start then move you mouse over the field moving left and right steps through the notes c to b and moving up and down will shift the pitch up or down an octave. Together the two axes give a sound map of the box so the position of the pointer can be heard.

Prototype 2: beacon prototype

This prototype keeps the same idea, position become sound but turns it into a search rather than a readout, instead of alwys hearing exactly where you are, a target is hidden somewhere in the box, and you have to find it, the note will rise and the ping speeds up the closer the user gets to it, panning tells you which direction to move and a short chord confirms when you land on it, i think this changes the feel of the itneraction more than i expected, the dot prototype is about claritiy, always knowing your position while the beacon is about search and uncertainty making it more engaging, especially for the audience of todlers who may not know where to go which goes with the use of exploration, this feels more closer to to how an instrument might reward exploration rather than just displaying infromation, moving forward this rasises a question about scale, how would this hold up with more than one hidden target at once, or across a much larger, scrollable box finding a point becomes a longer more deliberate search, and would this work with my intended audience

Prototype 3 cloud sound

This prototype explores the idea of using sound to understand where you are in a space, but instead of having one sound that changes depending on your position, the space is made up of different clouds or circles, that each represent a note, as you move through the closer you get to a cloud the louder and larger it's note becomes, allowing multiple notes to even blend together when you are between them this makes the space feel more like a musical instrument that can be explored by moving through it while still giving information about where you are with sound, i like how this changes the idea from reading your position to learning through different notes but in a simple way for my younger audience to explore, it also allows me to think about multiple sound at once and whether a more complex layout would still be understandable for the audience too

Idea 2 : Controls

This idea looks at how a note actually will get triggered, since for an instrument that choice changes what you can play not just how it feels, each version will use the same set of notes and the same layout of clouds, only the interaction for starting and stopping a sound being different

Prototype 1: toggle controls

This prototype explores a simple toggle interaction for starting and stopping notes, each one rperesents a different note, and tapping them starts a sound and changes it's appearance to show when that one is playing, tapping the name note again stops it and returns to the original state, i wanted to test whether this would makes the controls easy to understand becuase the user can see which notes exactly are currently playing rather than needing to remeber waht they have pressed, this makes the interaction more about choosing and combing sounds, at the same time compared to the other ideas, this version gaves the user more control over keeping the notes playing but it also means the user needs to turn off each sound themsleves

Prototype 2: hold controls

This prototype explores a hold interaction for starting and stopping notes, instead of tapping to keep a note playing the user has to press down and hold the cloud, and the note will stop as soon as they let go this makes the interaction feel more direct becuase the sound is connected to the users physical action, it also allows the user to quickly control how long each note phays and makes it harder to accidentally leave a note playing compard to the toggle prototype controls this version feels more responsive and playful, but it would make it harder to combine multiple notes because the user needs to keep holding each one down taking away the sense of exploration
